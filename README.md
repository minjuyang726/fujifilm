# 정기 설문 폐루프 에이전트 (한국후지필름형)

CX 담당자가 제품군별 대시보드로 설문과 외부 VOC를 보고, 액션 제안의 근거를 추적하고, 액션플랜과 다음 회차 설문지(초안)가 담긴 회차 리포트를 내보내는 웹 서비스입니다. 개인 프로젝트이고 배포하지 않았습니다.

> 이 저장소의 설문 응답은 **전부 합성 데이터**입니다. 설문에서 나온 수치는 성과가 아니며 화면에 "합성" 라벨이 고정으로 붙습니다. 정본 문서는 `docs/`와 `CLAUDE.md`입니다.

## 파이프라인

문항 → 취합 → 분석 → 액션플랜 → 다음 문항 초안

1. **취합**: 쿠팡 리뷰(CSV 적재)와 합성 설문 응답을 DB에 적재합니다.
2. **분석**: 코드가 제품군 × 회차별 계산표(스냅샷)를 만듭니다. 리뷰는 광고성 확률(LLM, `ad-v2`)을 구해 가중치 `max(0.1, 1 − p)`로 집계하고, 가중·비가중 집계를 모두 보여 줍니다.
3. **액션플랜**: 코드가 설문 q08에서 개선 영역 상위 3개와 순위 라벨을 정하고, LLM(`suggest-v6`)은 영역마다 우선순위 문장(값은 자리표시자)과 확인 칸이 있는 산출물 초안 틀(운영 사실이 필요한 자리는 "[확인 필요: …]" 칸으로 비어 있고 담당자가 채움)만 쓰며, 코드가 값 채우기·검증·근거 붙이기를 합니다. 쿠팡 리뷰 카드는 코드 템플릿입니다. 2026-11-03 호출 B를 4개 조합에서 다시 재실행해 최신 리포트의 액션 카드는 `suggest-v6` 결과입니다. 이전 리포트 행(`suggest-v3`~`suggest-v5`)은 DB에 남아 있습니다. 근거가 없는 문장은 리포트에 담지 않습니다.
4. **다음 문항 초안**: 코드 규칙이 불확실·불일치 가설을 찾고, 코드가 문항 형식(0~10 눈금 하나 또는 항목별 눈금)과 항목을 정하고, LLM(`question-v4`)은 문구(질문과 눈금 양끝 라벨)만 씁니다. 액션 카드가 있는 리포트에는 영역 확인 문항(코드 템플릿)이 맨 앞에 들어갑니다. 문항 초안의 상태는 항상 `draft`입니다. 마이그레이션 `b3defd1eaa82`를 적용하고 2026-11-03 호출 C를 4개 조합에서 재실행해 최신 리포트의 문항 초안은 `question-v4` 결과입니다. 이전 문항 행(`question-v3` 형식)은 DB에 남아 있습니다.
5. **리포트**: 액션플랜(영역 카드: 영역 라벨·순위 배지·우선순위 문장·"AI가 작성한 초안" 상자·확인 문항 번호)과 문항 초안(0~10 눈금 막대 미리보기, 응답용 화면이 아닌 정적 미리보기)을 한 화면에 보이고, 같은 구조를 인터넷 없이 열리는 독립형 HTML 한 파일로 내보냅니다(인쇄할 때 카드와 막대가 잘리지 않게 했습니다). 이전 형식(`suggest-v3` 문장, `question-v3` 문항) 결과도 기존 모양으로 표시합니다.

원칙: 계산은 코드가 하고 LLM은 코드가 계산한 표를 서술만 합니다. 광고성 판정은 글을 지우지 않고 가중치만 낮춥니다.

## 기술 스택

FastAPI, SQLAlchemy·Alembic, PostgreSQL(Supabase), React·Vite, pytest, OpenAI API (모델 `gpt-5.6-luna`). 근거: `CLAUDE.md`, `docs/spec.md`.

## 실행 명령 (PowerShell, `CLAUDE.md` 표 기준)

backend 폴더에서:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head          # DB 마이그레이션 (backend/.env의 DATABASE_URL 필요)
uvicorn app.main:app --port 8000   # API 문서: http://localhost:8000/docs
pytest
```

frontend 폴더에서:

```powershell
npm.cmd install
npm.cmd run dev               # http://localhost:5173
npm.cmd run build
npm.cmd run lint
```

주요 스크립트는 backend 폴더에서 `python scripts/<이름>.py`로 실행합니다: `load_reviews`, `pilot_sample`, `generate_synthetic_survey`, `load_synthetic_survey`, `seed_families`, `verify_voc_dashboard`, `verify_snapshot`, `verify_hypotheses`, `estimate_suggestion_cost`, `estimate_question_cost`. 각 스크립트의 인수와 확인 상태는 `CLAUDE.md`의 실행 명령 표에 있습니다. 환경 값은 `backend/.env`(비밀 값)와 `frontend/.env`(backend 주소)에 넣고, 항목 이름은 각 폴더의 `.env.example`에 있습니다. 키와 접속 문자열은 저장소에 올리지 않습니다.

## 한계

- 설문 응답은 합성이고 제품군 구분 없이 회차 공통(`family_id` 없음)입니다. 두 제품군의 설문 수치는 같습니다.
- 광고성 판정 표본이 작습니다. 회차·제품군별 판정 묶음은 4~7건이고, 사람 라벨 비교는 31건이며 광고성 라벨이 2건뿐입니다. 가중 전후 차이가 작아 가중 효과는 주장하지 않습니다.
- 임계값은 근거 없는 가정입니다: 표본 적음 30건 미만, 1·2위 격차 1.96×SE(R2′), 만족 60%·추천 안 함 50%, 가중치 하한 0.1.
- 문항 품질은 평가하지 않았습니다. 코드 검증은 형식·숫자·금지 단어만 봅니다.
- 문항 보기 표현이 겹칠 수 있습니다(예: "가끔 사용함"과 "때때로 사용함"). 숫자 금지 규칙 때문에 원문항의 구간 보기와 후속 문항의 보기를 비교할 수 없습니다. (`question-v3` 결과에 해당합니다. `question-v4`는 보기를 모델이 쓰지 않고 코드가 설문 문항 정의에서 공급합니다.)
- 문항 초안의 보기끼리 의미가 겹칠 수 있습니다(예: 가끔 사용함/때때로 사용함). 프롬프트 개선은 하지 않았고 검증기도 없습니다. (`question-v3` 결과에 해당합니다. `question-v4`는 보기를 모델이 쓰지 않고 코드가 설문 문항 정의에서 공급합니다.)
- 산출물 초안은 suggest-v6 기준으로 종류별 초안 문구이며, 운영 사실이 필요한 자리는 "[확인 필요: …]" 칸으로 비어 있습니다. 에이전트는 현재 운영 사실을 알 수 없으므로 칸은 담당자가 채웁니다. 카드의 초안은 검토·수정이 필요합니다.
- 영역 목록이 제품군 공통이어서 제품군별 서비스 유무를 코드가 판단하지 않습니다. 산출물은 해당 절차의 유무 자체를 칸으로 둡니다.
- v5에서는 제품군에 없는 서비스를 전제하는 표현과 근거 없는 점검 항목이 나온 사례가 있었고, v6에서 프롬프트 규칙(서비스·절차 가정 금지, 점검 항목 근거 제한, "현재 …" 전제 금지)으로 줄였습니다. 코드 검증기는 "현재 …" 전제 표현만 막고, 서비스 단정과 근거 없는 항목은 코드가 판정하지 못해 프롬프트 규칙으로만 막습니다. 운영 사실 단정 금지 목록(예상 기간, 결제 금액, 재고, 판매 단위 등)도 완전하지 않고, 합니다체는 프롬프트로만 지시하며 코드가 검사하지 않습니다.
- 같은 설문 데이터라도 문항 문구는 호출마다 달라질 수 있습니다(항목과 눈금은 코드가 정하고 문구만 모델이 씁니다).
- 영역 카드의 리뷰 근거는 0건이고 우선순위는 합성 설문으로만 정했습니다. 판정이 끝난 리뷰 표본은 제품군×회차당 4~7건입니다.
- 다음 회차 문항 초안이 눈금형으로 바뀌면 이번 회차의 범주형 응답과 직접 비교할 수 없습니다. 실제 운영에서는 핵심 문항 형식을 고정해야 합니다.
- 눈금 양끝 라벨은 모델이 쓴 초안입니다. 서로 의미가 반대인지는 코드가 가리지 못합니다.
- 합성 설문(n=100)으로는 세 영역의 순위를 가리지 못해(네 조합 모두 공동 1순위) 영역 확인 문항으로 다음 회차에 가립니다.
- 반복 호출 일치율(NFR-R1)은 확인하지 못했습니다. 정기 실행(n8n, Phase 7)은 구현하지 않았습니다(`docs/plan.md`).
- 데이터 품질 점검 결과(회차 밖 리뷰 비율, 표본 크기, 합성 설문 구조, 수집 기록 미확인 등)는 `docs/data_quality.md`에 있습니다.
- 개인정보·약관 등 법적 적합성은 이 코드와 문서로 보증하지 않습니다(`CLAUDE.md`).
