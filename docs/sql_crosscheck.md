# SQL 교차검증 (부록 B)

상태: **2026-11-02에 쿼리를 실행해 대조표를 채웠다. 모든 수치는 실측이고 추출 시점 기준이다.** 근거는 [plan.md](plan.md) 부록 B(승인됨, 2026-11-01)다. 포트폴리오 전용 작업이며 Phase 순서와 게이트를 대신하지 않는다.

이 문서는 부록 A 데모(`GET /api/demo/review-stats`)가 파이썬으로 센 집계를 SQL로 다시 세어 건수 단위로 대조한 기록이다. 표의 수치는 2026-11-02에 파이썬 응답과 SQL 결과를 직접 대조한 결과다.

## 1. 집계 기준

기준은 `backend/app/services/review_stats.py`에 있는 것만 옮겼다.

| 항목 | 기준 | 코드 |
| --- | --- | --- |
| 상품별 리뷰 수 | 상품(`product_name`)별 행 수 | `aggregate_review_stats` |
| 평점 분포 | 1~5점 다섯 칸, 없는 점수는 0 | `RATINGS`, `aggregate_review_stats` |
| 상품 순서 | 이름순(파이썬 `sorted`, 유니코드 코드포인트 순서) | `aggregate_review_stats` |
| 분기 | `review.date`의 달력 분기 `(월 − 1) // 3 + 1`, 표기 `YYYY-Qn` | `_quarter_key`, `_quarter_label` |
| 빈 분기 | 데이터의 첫 분기부터 마지막 분기까지 0건으로 채움 | `aggregate_review_stats` |

| 평점 범위 | 1~5 밖이면 오류 | `aggregate_review_stats` |

## 2. 쿼리별 사용 구조

모든 쿼리는 PostgreSQL 전용 SELECT이고, 리뷰 원문·제목·작성자를 결과에 내지 않는다. 파일은 저장소 루트 `sql/`에 있다.

| 파일 | 하는 일 | JOIN | GROUP BY | 서브쿼리 | CTE | 기타 |
| --- | --- | --- | --- | --- | --- | --- |
| `sql/01_rating_distribution.sql` | 상품별 리뷰 수, 평점 1~5점 건수 | `product` ⋈ `review`(외래키) | 상품 | - | - | `COUNT(...) FILTER`, `COLLATE "C"` |
| `sql/02_quarterly_counts.sql` | 분기별 건수, 빈 분기 0건 | `quarters` ⟕ `counts` | 분기 | - | `bounds`, `quarters`, `counts` | `date_trunc`, `generate_series`, `to_char` |
| `sql/03_text_presence.sql` | 상품별·합계 본문 있는 건수와 비율 | - | 상품 | 합계 행과 비율 분모 | `flagged`, `per_product` | `btrim(문자 목록)`, `UNION ALL`, `ROUND(numeric, 4)` |
| `sql/04_whitespace_check.sql` | 파이썬 `strip()`과 SQL 공백 처리가 달라지는 행의 건수 | - | - | - | - | 세 정의(파이썬 동등 / 단순 trim / 정규식) 비교, 한 줄 출력 |

## 3. 실행 방법 (사용자가 한다)

결정 7(plan.md 부록 B)에 따라 Claude Code는 DB에 접속하지 않는다.

1. Supabase SQL 편집기에서 `sql/01~04` 파일의 SELECT를 하나씩 그대로 실행한다. `BEGIN READ ONLY` / `ROLLBACK` 래퍼는 쓰지 않는다.
2. 파일에는 SELECT만 있고 쓰기 구문이 없다. 실행 전에 눈으로 확인한다.
3. 편집기가 마지막 구문 결과만 보여 줄 수 있어 래퍼는 결과를 가릴 수 있다(확인 필요).
4. 결과에서 **집계 숫자만** 전달한다. 접속 문자열은 공유하지 않는다.

파이썬 쪽 값은 부록 A 데모 API 응답(`GET /api/demo/review-stats`)의 집계 숫자를 쓴다. 이 응답에는 리뷰 본문, 제목, 작성자가 없다.

## 4. 파이썬과 SQL이 다를 수 있는 곳 (실행 전 추정을 2026-11-02 실행 결과와 대조함)

아래는 쿼리를 실행하기 전 작성 시점의 추정이고, 2026-11-02에 쿼리를 실행해 5절에서 대조한 기록이다.

| 번호 | 지점 | 가능한 차이 | 확인하는 곳 |
| --- | --- | --- | --- |
| 1 | 상품 정렬 | DB의 정렬 규칙에 따라 한글 상품명 순서가 파이썬과 다를 수 있다. 쿼리는 `COLLATE "C"`로 코드포인트 순서에 맞췄다 | 01, 03의 결과 순서 |
| 2 | 리뷰 없는 상품 | 파이썬 결과에는 리뷰가 있는 상품만 나온다. 쿼리는 INNER JOIN이라 같은 기준이다. LEFT JOIN으로 바꾸면 0건 상품이 보인다 | 01 |
| 3 | 공백 범위 | 파이썬 `strip()`과 SQL `trim`은 지우는 문자가 다르다. `btrim`의 문자 목록은 파이썬 `isspace()` 범위를 옮긴 것이고 목록이 같은지는 2026-11-02 실행 결과와 대조함(5.4) | 04 |
| 4 | 반올림 | 파이썬 `round()`는 이진 부동소수점을 짝수 쪽으로, PostgreSQL `ROUND(numeric)`는 0.5를 올림한다. 다섯째 자리가 정확히 5로 끝나는 경우만 다를 수 있다 | 03 비율 |
| 5 | 분기 경계 | `date`를 `timestamp`로 바꿔 `date_trunc`를 쓴다. 시간대 영향은 없는 것으로 설계했고 2026-11-02 실행 결과와 대조함(5.2) | 02 |
| 6 | 보이지 않는 문자 | U+200B 같은 문자만 있는 본문은 파이썬에서 "본문 있음"이다. SQL 정의 (P)도 같다. 그런 행이 있는지만 센다 | 04 `only_zero_width_count` |

### 5.5 판정

- 모든 행이 일치했고, 불일치 행은 없다.
- **이번 데이터(1,302건)에서의 일치이며, 일반화하지 않는다.**
- **반올림 차이는 이번 데이터에서 드러나지 않았다.** 상품 1의 파이썬 0.139와 SQL 0.1390은 같은 값이며 자릿수 표기만 다르다.
- 공백 처리는 세 정의 (P)(N)(R)가 모두 297건이고, 정의가 달라지는 행과 보이지 않는 문자만 있는 행이 모두 0건이었다. 이번 데이터에서는 정의 차이가 드러나지 않았다.
- 2026-Q4는 추출 시점(2026-11-02)까지의 부분 기간이다.
- 직접 출력한 값이 아닌 칸은 하나다: 파이썬의 "1~5 밖 평점 건수 0"은 범위 밖이면 오류를 내는 구조이고 응답이 정상이었다는 점에서 추론한 값이다.

## 6. 한계와 확인하지 못한 것

- 2026-11-02에 쿼리를 실행했고 오류 없이 완료됐다.
- SQL의 `btrim` 문자 목록은 파이썬 `isspace()` 범위를 옮긴 것이다. 2026-11-02 실행에서 04의 파이썬 동등 정의(P)=297, 단순 trim(N)=297, 정규식(R)=297이고 차이 행이 0건이어서 이번 데이터에서 정의 차이가 드러나지 않았다. 다른 데이터에서의 일치는 보장하지 않는다.
- 운영 DB 접속 계정의 권한(읽기 전용인지)은 확인하지 않았다. 래퍼 없이 SELECT만 실행했다(편집기가 마지막 구문 결과만 보여 줄 수 있어 래퍼는 결과를 가릴 수 있음, 확인 필요).
- 운영 DB 스키마가 마이그레이션과 같은지는 확인하지 않았다.
- 대조 결과를 파이썬 쪽 숫자와 사람이 눈으로 맞추는 방식이다. 자동 대조는 만들지 않았다.
- 집계 CSV는 만들지 않았다. 필요하면 추적하지 않는 로컬 파일로 만든다(plan.md 부록 B 결정 6).
