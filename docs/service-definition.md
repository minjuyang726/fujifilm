# 서비스 정의

한국후지필름형 정기 설문 폐루프 에이전트의 사용자, 불편, 핵심 행동을 정리한 문서입니다.

## 표기 규칙

| 표기 | 의미 |
| --- | --- |
| 결정 | 프로젝트에서 우리가 정한 내용. 후지필름에서 확인된 사실이 아님 |
| 가정 | 설계를 진행하기 위해 둔 가정. 후지필름에서 확인된 사실이 아니며, 실제 값은 본선 자료 또는 주최 측 문의로 확인 (현재 미확인) |
| 설계 제안 | 가정이 아니라 설계 결정으로 제안하는 내용. 아직 설계 문서에 정의되어 있지 않음 |
| 미정 | 결정되지 않은 내용 |
| 사이트 기준 | 과제명과 과제 문구처럼 공모전 사이트에 적힌 내용. 후지필름의 서비스·운영에 대한 사실은 아님 |

후지필름의 서비스·운영과 관련해 확인된 사실은 이 문서에 없습니다. "사이트 기준" 표기는 공모전 사이트에 적힌 과제명과 과제 문구에만 붙입니다.

도구(엑셀, 외부 설문 툴 등)는 일반적인 예시이며, 이 문서에서는 특정 제품명 대신 "기존 도구와 연동하는 입력 어댑터"로 표현합니다.

## 용어

- **회차**: 정기 설문 한 번의 실시 단위. 설문 실시부터 분석, 리포트, 다음 회차 설문지 준비까지가 한 회차다.
- **VOC**: 설문 밖에서 모은 외부 고객 목소리. 수집은 정기 자동 실행이 맡으며 담당자의 행동이 아니다. 현재 입력은 쿠팡 후지필름 리뷰 CSV(상품 3개)와 네이버 블로그·카페 글(보강 예정)이다. (취소됨, 결정 2026-11-03)
- **불확실·모순 가설**: 한 회차의 분석 후에도 결론이 나지 않았거나 결과끼리 어긋나서, 다음 회차 문항으로 다시 확인해야 하는 가설. 설계 문서에는 이 용어가 정의 없이 쓰이고 있으므로, 이 문서의 풀이를 기준으로 삼는다.
- **근거 ID**: 제안 문장이 가리키는 응답·리뷰의 식별자.
- **근거 뷰어**: 근거 ID로 원래 응답·리뷰를 열어 보는 화면.
- **Phase 0**: 개발 초기의 데이터 적재·품질 감사 단계. 세부 내용은 plan.md에서 정의한다.

## 서비스 요약 (결정, 과제명·과제 문구는 사이트 기준)

한국후지필름형 정기 설문 폐루프 에이전트. 사용자는 소비자가 아니라 CX 담당자이고, 결과물은 제품군별 CX 웹 대시보드와 회차 리포트(액션플랜 + 다음 회차 설문지)다.

## 1. 사용하는 사람

사용자는 CX 담당자입니다 (결정: 과제를 가정한 페르소나이며 실제 사용자 조사는 아님). 아래 세부 내용은 모두 가정이며 현재 미확인입니다.

| 항목 | 가정 | 설계에 주는 영향 |
| --- | --- | --- |
| 팀 규모와 담당 분리 | 소규모 CX 팀(수 명)이 쓰고, 담당자는 제품군을 나눠 맡거나 겸임. 한 사람이 여러 제품군을 볼 수 있음 | 첫 화면에서 제품군을 고르는 구조. 로그인·권한 분리는 이번 범위에서 제외 |
| 보는 사람 구분 | 담당자는 대시보드와 근거 뷰어를 직접 보고, 의사결정자(팀장·임원)는 회차 리포트만 받음 | 담당자용은 상세 대시보드, 의사결정자용은 한 문서로 읽히는 회차 리포트 |
| 회차 주기 | 분기 단위로 가정 (근거 없음. 월 단위는 준비 부담이 크고 반기 이상은 "정기" 느낌이 약하다는 판단) | 시연에서는 회차를 압축해 보여주고, 주기는 n8n 스케줄 설정값으로 변경 가능 |

## 2. 겪는 불편

아래 현재 방식과 불편은 일반적인 소비재 기업의 정기 설문 운영을 가정한 흐름이며, 후지필름에서 확인된 사실이 아닙니다. 실제 운영 방식과 사용 도구는 본선에서 제공되는 자료로 확인합니다.

| 단계 | 가정한 현재 방식 | 가정한 불편 | 에이전트가 맡는 부분 |
| --- | --- | --- | --- |
| 1. 설문지 제작 | 지난 회차 설문지와 컨설팅 자료를 참고해 엑셀·문서로 문항을 수동 작성하고 외부 설문 툴에 입력 | 회차마다 반복 작업이고, 이전 분석의 의문이 문항에 반영되는지가 담당자 기억에 의존 | 이전 회차의 불확실 가설로 문항 초안 생성 |
| 2. 발송 | 외부 설문 툴의 링크나 이메일로 배포 (설문 대상은 알 수 없음) | - | 범위 밖. 기존 방식 유지 |
| 3. 응답 취합 | 설문 툴에서 응답을 엑셀로 내려받아 정리 | 회차별 파일이 흩어지고 형식이 달라질 수 있음 | 입력 어댑터로 응답 구조를 표준화해 적재 |
| 4. 분석 | 엑셀 피벗·차트로 문항별 집계와 집단 비교 | 외부 고객 목소리와 설문 결과가 따로 분석됨 | 설문 집계와 외부 VOC 분석을 제품군별로 결합 |
| 5. 보고·제안 | 결과를 문서나 슬라이드로 정리해 보고하고 액션을 논의 | 제안의 근거 응답을 추적하기 어렵고 작성에 시간이 듦 | 코드로 계산한 표만 입력받아 제안 서술, 근거 ID 연결 |
| 6. 다음 회차 반영 | 보고 내용을 사람이 해석해 다음 설문지에 수동 반영 | 분석에서 남은 의문이 다음 문항으로 이어지지 않을 수 있음 | 불확실·모순 가설을 다음 회차 문항 초안으로 변환 |

## 3. 서비스에서 할 수 있어야 하는 핵심 행동

담당자 관점의 행동입니다. 번호는 업무 흐름 순서이고, MVP 포함 여부(mvp.md 기준)에 따라 두 묶음으로 나눴습니다. 각 행동의 확인 기준은 이 문서에서 제안하는 초안이며, prd.md와 plan.md를 쓸 때 다듬습니다.

### 3.1 결정 행동 (3, 4, 6)

**행동 3. 제품군별 결과 확인**
제품군을 골라 설문 집계와 외부 VOC가 결합된 결과를 대시보드에서 본다.
- 가중/비가중을 토글로 전환해 볼 수 있다. 토글은 외부 VOC의 광고성 가중치(1 − 광고성 확률, 결정)에만 적용된다. 설문 응답(KOSSDA) 집계는 두 자료에 가중치 변수가 없어 비가중으로 집계한다. 가중치 하한은 파일럿에서 정한다(미정).
- 제품군 목록은 미정이다. 상품 3개를 제품군으로 묶는 방식은 제품군 사전 작업에서 확정한다(mvp.md 참고).
- 회차별 문항 결과를 확인할 수 있다.
- 합성 응답에는 "합성" 라벨이 붙으며, 담당자가 보는 요소에 포함된다.
- 확인 기준: 제품군을 고르면 설문 집계와 VOC가 한 화면에 나온다. 외부 VOC의 가중/비가중을 바꾸면 VOC 집계 결과가 바뀌고, 설문 응답 집계는 토글과 무관하게 비가중이다. 회차를 고르면 해당 회차의 문항 결과가 나온다. 화면에 표시된 수치가 집계 원본과 일치한다.

**행동 4. 근거 추적**
액션 제안마다 근거 ID로 근거 응답을 근거 뷰어에서 추적한다.
- 확인 기준: 액션 제안의 근거 ID를 선택하면 해당 근거 응답이 근거 뷰어에 열린다. 모든 제안 문장이 근거 ID를 가진다.

**행동 6. 회차 리포트 내보내기**
액션플랜과 다음 회차 설문지가 담긴 회차 리포트를 내보낸다.
- 리포트 속 "다음 회차 설문지"는 초안 상태로 담긴다. 행동 1(문항 초안 확정)을 MVP에서 제외하기로 했기 때문이다.
- 시스템은 리포트 출력과 내보내기까지만 맡는다.
- 내보낸 리포트를 의사결정자에게 전달하는 일은 시스템 밖의 수작업이며 범위 밖이다 (전달 방식은 미정).
- 확인 기준: 한 회차의 액션플랜과 다음 회차 설문지가 한 리포트로 내보내진다.

### 3.2 후보였다가 MVP에서 제외한 행동 (1, 2, 5)

사람 검토 단계(1, 5)와 업로드 화면(2)은 MVP에 넣지 않기로 했습니다(mvp.md 기준). 아래는 이 행동들이 무엇이었는지 기록으로 남긴 것이며, 이 행동들은 MVP에 들어가지 않습니다.

**행동 1. 문항 초안 확정** (설계 제안, MVP 제외로 결정)
이전 회차의 불확실·모순 가설로 만든 문항 초안을 확인·수정해 확정한다.
- 설계 문서에는 "초안 생성"까지만 정의되어 있고, 담당자의 수정·승인 단계는 정의되어 있지 않다. 신뢰성 항목에 "사람 검토 단계"가 있어 사람이 개입한다는 방향만 잡혀 있다.
- 이 행동의 산출물은 행동 6의 리포트 안에 있는 "다음 회차 설문지"와 같다. 이 행동은 다음 회차 준비 시점에 그 설문지를 꺼내 보는 행동으로 구분한다.
- 확인 기준: 이전 회차의 불확실·모순 가설이 문항 초안으로 나오고, 담당자가 수정한 뒤 확정할 수 있다.

**행동 2. 응답 파일 적재** (업로드 화면은 MVP 제외로 결정)
기존 도구에서 내려받은 응답 파일을 넣으면, 입력 어댑터가 표준화해 적재한다.
- 적재는 시스템이 하는 일이고, 담당자 행동은 파일을 시스템에 넣는 것이다.
- 이번 시연에서는 KOSSDA 구조와 합성 응답을 쓴다. 담당자 업로드 화면은 MVP에서 제외한다. (결정)
- 응답 데이터는 개발 초기의 데이터 적재 단계(Phase 0)에서 스크립트로 적재한다. 행동 3, 4는 적재된 데이터로 동작한다.
- 확인 기준: 응답 파일을 넣으면 표준화된 형태로 적재되어 행동 3의 대시보드에 나타난다.

**행동 5. 액션 제안 선별·수정** (설계 제안, MVP 제외로 결정)
회차 리포트를 내보내기 전에 담당자가 액션 제안을 선별·수정한다.
- 이 단계가 정의되어 있는지는 확인되지 않았다. 행동 1과 같은 사람 검토 단계로 묶어 함께 정한다.
- 행동 4의 "모든 제안 문장이 근거 ID를 가진다"와 충돌하지 않도록, 수정한 제안도 근거 ID가 유지되어야 한다. 담당자가 새로 쓴 제안에 근거를 어떻게 붙일지는 미정이지만, 이 행동이 MVP에서 제외되었으므로 MVP에서는 다루지 않는다.
- 확인 기준: 담당자가 선별·수정한 액션 제안만 리포트에 반영되고, 수정 후에도 근거 ID가 유지된다.

## 범위 밖

- 설문 발송: 기존 방식 유지 (설문 대상은 알 수 없음)
- 로그인·권한 분리 (이번 범위에서 제외)
- 내보낸 리포트를 의사결정자에게 전달하는 일 (시스템 밖 수작업)
- VOC 수집 실행: 정기 자동 실행(n8n)이 맡으며 담당자 행동이 아님
