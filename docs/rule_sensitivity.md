# 가설 규칙 민감도

측정일 2026-11-03. 수치는 `backend/scripts/rule_sensitivity.py`가 Supabase를 읽기 전용(`SET TRANSACTION READ ONLY`)으로 조회해 제품군 × 회차 4개 조합의 스냅샷 표를 메모리에서 계산한 결과이고, 아무것도 저장하지 않았다. OpenAI는 부르지 않았다. 설문 수치는 합성이고 성과로 쓰지 않는다. 실측은 판정 묶음의 건수와 평균 평점이다. 모든 임계값은 근거 없는 가정이다.

## 1. 규칙 정의

구현은 `backend/app/services/hypotheses.py`, 정의는 `docs/spec.md`의 hypothesis 절이다. 가설은 코드 규칙만으로 찾고 LLM은 관여하지 않는다. 화면의 "불일치"는 코드의 `kind = contradictory`와 같은 것이다(코드·DB 값은 바꾸지 않았다).

| 규칙 | 종류 | 조건 | 단위 |
| --- | --- | --- | --- |
| R1 | 불확실 | VOC 판정 묶음 n < 30 | 제품군 × 회차의 판정 묶음 |
| R2′ | 불확실 | `single` 문항의 1·2위 비율 p1, p2와 문항 응답 수 n에 대해 격차 ≤ 1.96 × SE, SE = √((p1 + p2 − (p1 − p2)²) / n), 경계 포함 | `single` 문항 (q06, q07, q09, q10) |
| R3 | 불일치 | q01의 4·5점 합 ≥ 60% 이고 q09 "아니오" ≥ 50% | 문항 쌍 q01 × q09 |
| R4 | 불일치 | q01의 4·5점 합 ≥ 60%인데 판정 평균 평점 ≤ 3.5, 또는 합 < 50%인데 평균 ≥ 4.5 (판정 1건 이상) | 설문 q01 × 판정 묶음 평균 |

- R2′는 이전의 고정 격차 5%p 기준을 바꾼 것이다(결정 2026-11-03, 사용자 지시). 가설을 정렬하는 방식(격차가 작은 순), 우선순위(불일치 > R2′ > R1), 한 스냅샷 최대 5개는 그대로다.
- R3는 서로 다른 문항의 집계 비율을 나란히 놓은 것이며 같은 응답자의 모순을 뜻하지 않는다.
- R1 30건, R3 60/50, R4 값은 바꾸지 않았다.

## 2. 민감도 표

설정별로 걸리는 가설 수이며 상한(5개)과 우선순위는 적용하지 않은 규칙별 개수다.

| 설정 | 제품군 1 × 2026-Q1 | 제품군 1 × 2026-Q2 | 제품군 2 × 2026-Q1 | 제품군 2 × 2026-Q2 |
| --- | --- | --- | --- | --- |
| R1: 판정 n < 20 | 1 | 1 | 1 | 1 |
| R1: 판정 n < 30 (현재) | 1 | 1 | 1 | 1 |
| R1: 판정 n < 50 | 1 | 1 | 1 | 1 |
| R2: 고정 격차 ≤ 3%p | 3 | 1 | 3 | 1 |
| R2: 고정 격차 ≤ 5%p (이전 기준) | 3 | 1 | 3 | 1 |
| R2: 고정 격차 ≤ 10%p | 3 | 3 | 3 | 3 |
| R2′: 격차 ≤ 1.96 × SE (현재) | 3 | 3 | 3 | 3 |
| R3: 만족 ≥ 50, 비추천 ≥ 40 | 1 | 0 | 1 | 0 |
| R3: 만족 ≥ 60, 비추천 ≥ 50 (현재) | 1 | 0 | 1 | 0 |
| R3: 만족 ≥ 70, 비추천 ≥ 60 | 0 | 0 | 0 | 0 |
| R4 (현재 상수) | 0 | 0 | 0 | 0 |

입력 값(합성 설문 n = 100, 판정 묶음은 실측):

| 조합 | 판정 n | q01 4·5점 합 | q09 "아니오" | 판정 평균 평점(비가중) |
| --- | --- | --- | --- | --- |
| 제품군 1 × 2026-Q1 | 7 | 67.0% | 51.0% | 4.2857 |
| 제품군 1 × 2026-Q2 | 4 | 75.0% | 39.0% | 5.0 |
| 제품군 2 × 2026-Q1 | 4 | 67.0% | 51.0% | 5.0 |
| 제품군 2 × 2026-Q2 | 7 | 75.0% | 39.0% | 4.8571 |

R2′ 문항별 값 (n = 100, 두 제품군이 같다. 칸은 격차 / 임계 1.96 × SE, 단위 %p):

| 문항 | 2026-Q1 | 2026-Q2 |
| --- | --- | --- |
| q06 | 3.0 / 14.26 → 걸림 | 2.0 / 13.57 → 걸림 |
| q07 | 21.0 / 14.48 → 안 걸림 | 10.0 / 14.27 → 걸림 (이전 기준에서는 안 걸림) |
| q09 | 2.0 / 19.60 → 걸림 | 22.0 / 19.12 → 안 걸림 |
| q10 | 0.0 / 14.67 → 걸림 | 7.0 / 13.93 → 걸림 (이전 기준에서는 안 걸림) |

## 3. 해석 (위 값으로 한정)

- 현재 데이터에서 R2′는 이전 R2의 상위 호환이다. 이전 기준에 걸리던 문항은 모두 R2′에도 걸려서 사라진 가설은 0개다. 새로 걸리는 가설은 2026-Q2의 q07(격차 10.0%p)과 q10(격차 7.0%p)이고 두 제품군에서 같다.
- 결과적으로 한 스냅샷의 가설은 2026-Q1이 5개(R3 1, R2′ 3, R1 1)로 그대로이고, 2026-Q2가 2개에서 4개(R2′ 3, R1 1)로 늘었다. 호출 C의 문항 대상(R1 제외)은 2026-Q2에서 1개에서 3개가 된다.
- R1은 판정 n이 4~7이라 임계 20, 30, 50에서 결과가 같다.
- R2는 고정 격차 3%p와 5%p에서 결과가 같고, 10%p와 R2′에서는 2026-Q2의 개수가 3으로 늘어난다.
- R3는 2026-Q1에서 q09 "아니오"가 51.0%로 임계 50%에 가깝고, 70/60 설정에서는 0건이다. 2026-Q2는 "아니오" 39.0%라 (50, 40) 설정에서도 0건이다. 이 비율은 합성 설문의 값이다.
- R4는 현재 데이터에서 걸리지 않는다.
- 설문은 합성이며 제품군 공통이라 설문 쪽 가설(R2′, R3)은 두 제품군에서 같다. 두 제품군을 가르는 것은 R1과 R4가 쓰는 판정 묶음뿐이다.
- 모든 임계는 가정이며, 이 표는 임계가 바뀔 때 건수가 어떻게 달라지는지만 보여 준다. 어느 설정이 맞는지는 판단하지 않았다.

## 4. 영향과 호출 C 비용 추정

- 이 변경으로 DB에 저장된 기존 가설, 문항 초안, 리포트는 바뀌지 않는다. 2026-11-03 호출 C를 4개 조합에서 재실행했고, 실제 비용은 $0.002690이다. 2026-11-03 호출 B(suggest-v4)와 호출 C(question-v4)를 4개 조합에서 재실행했고, 실제 비용은 $0.007722이다. 같은 날 호출 B(suggest-v5)와 호출 C(question-v4, 같은 원문항 가설 합치기 반영)를 4개 조합에서 다시 재실행했고, 실제 비용은 $0.007106이다.
- 비용 추정기(`scripts/estimate_question_cost.py`, 읽기 전용, OpenAI 호출 없음, 계수는 가정)를 새 규칙으로 실행한 결과: 문항 대상 가설 수 4 / 3 / 4 / 3(제품군 1·2 × Q1·Q2 순), 한 번씩 호출할 때 합계 $0.0074, 재시도 배수 3을 적용한 상한 합 $0.0222이며 한도 $0.50을 넘지 않는다. 호출 B(액션 제안)의 입력은 스냅샷 표라서 이 변경과 무관하다.

## 5. 한계

- 다항분포에서 같은 응답자의 두 비율 차이에 대한 근사이며, 1·2위를 데이터를 본 뒤에 고르고 4개 문항을 보정 없이 검정하므로 R2′의 불확실성 판단은 관대할 수 있다.
- 임계값(R1 30건, R2′ 1.96, R3 60/50, R4 3.5/4.5, 가설 5개)은 모두 근거 없는 가정이다. 이 데이터로 검증하지 않았다.
- 설문은 합성이고 응답자 100명이라 R2′의 임계(약 13.6~19.6%p)가 넓다. 응답 수가 달라지면 같은 비율에서도 결과가 달라진다(`tests/test_hypotheses.py`에 n = 100과 n = 1000 비교가 있다).
- 판정 묶음은 4~7건이라 R1과 R4의 입력이 작다.
- 4개 조합이라 민감도 표의 표본이 작다.

## 6. 재현 방법

backend 폴더에서 PowerShell로 실행한다. `backend/.env`의 `DATABASE_URL`이 필요하고 DB는 읽기만 한다.

```powershell
.venv\Scripts\python.exe scripts/rule_sensitivity.py
.venv\Scripts\python.exe scripts/verify_hypotheses.py
```

`verify_hypotheses.py`는 R2′를 포함해 규칙 결과를 SQL 재계산과 비교한다(2026-11-03, 4개 조합 모두 같음, 문제 0건).
