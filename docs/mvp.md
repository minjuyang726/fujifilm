# MVP 정의

한국후지필름형 정기 설문 폐루프 에이전트의 MVP 범위를 정리한 문서입니다. 범위의 근거는 [service-definition.md](service-definition.md)입니다. 이 문서에서 새로 추가한 기능은 없습니다.

## 표기 규칙

표기 규칙은 service-definition.md를 따릅니다(결정, 가정, 설계 제안, 미정). 수치에는 아래 중 하나를 반드시 붙입니다.

| 수치 표기 | 의미 |
| --- | --- |
| 실측 | 실제 데이터에서 센 값 |
| 가정 | 설계를 위해 둔 값. 출처 없음 |
| 합성 | 합성 응답에서 나온 값. 성과로 쓰지 않음 |

## 1. 해결하려는 문제

정기 설문을 운영하는 CX 담당자는 회차마다 설문지를 만들고, 응답과 외부 고객 목소리(VOC)를 따로 분석하고, 제안의 근거를 일일이 찾아 보고서를 씁니다. 분석에서 남은 의문은 다음 회차 문항으로 이어지는지가 담당자 기억에 달려 있습니다.

이 서비스는 설문과 VOC를 제품군별로 결합해 보여주고, 제안마다 근거 응답을 추적하게 하고, 다음 회차 설문지까지 담은 회차 리포트를 내보내 이 흐름을 닫는 것이 목표입니다.

- 위 불편은 모두 **가정**입니다. 일반적인 소비재 기업의 정기 설문 운영을 가정한 흐름이며, 후지필름에서 확인된 사실이 아닙니다. 실제 운영 방식은 본선 자료로 확인합니다.

## 2. 사용자

- **CX 담당자**: 대시보드와 근거 뷰어를 직접 쓴다. (결정: 과제를 가정한 페르소나이며 실제 사용자 조사는 아님)
- **의사결정자(팀장·임원)**: 시스템을 직접 쓰지 않고, 내보낸 회차 리포트만 받는다. (가정)
- 소규모 CX 팀이 제품군을 나눠 맡거나 겸임한다. 한 사람이 여러 제품군을 볼 수 있다. (가정, 미확인)
- 회차 주기는 분기 단위로 가정한다. 근거는 없다. (가정)

## 3. 사용할 데이터

| 데이터 | 내용 | 표기 |
| --- | --- | --- |
| 쿠팡 후지필름 리뷰 CSV | 총 1,302건. 외부 VOC 입력(자유서술 VOC)의 일부 | 실측 |
| 　텍스트가 있는 리뷰 | 297건 | 실측 |
| 　상품별 건수 | QuickSnap 541건, mini EVO 410건, MINI12 351건 (합계 1,302건) | 실측 |
| 네이버 블로그·카페 글 | 텍스트가 부족해서 보강하는 VOC 입력. 수집은 진행 전이며 건수는 측정 예정 | 수치 없음 |
| KOSSDA 자료 15683 (주) | 설문 응답 구조를 따르기 위한 참고 자료. 두 자료 모두 가중치 변수가 없음(변수명·라벨 키워드 검색, 코드북 PDF 검색 기준) | 자료 번호이며 수치 아님 |
| KOSSDA 자료 14488 (보조) | 위와 같음 | 자료 번호이며 수치 아님 |
| 합성 응답 | KOSSDA 구조를 따라 만든 응답. 건수는 미정. "합성" 라벨을 고정한다 | 합성 |

- 합성 응답에는 화면에서 "합성" 라벨을 붙인다. 합성 응답에서 나온 수치는 성과로 쓰지 않는다.
- 외부 VOC 입력: 쿠팡 후지필름 리뷰 CSV(상품 3개) + 네이버 블로그·카페 글(보강 예정). 쿠팡 CSV만으로는 텍스트가 있는 리뷰가 297건(실측)이라 네이버 글로 보강한다.
- 위 세 개는 제품군이 아니라 **상품**이다. CSV의 상품명은 "후지 QuickSnap 일회용 카메라 400/27", "인스탁스 mini EVO 즉석카메라 FI019 풀패키지 세트", "인스탁스 즉석카메라 클레이화이트 + 가방 + 필름 10p x 2팩 + 스트랩 세트 MINI12"이다.
- 제품군: 미정. 상품 3개를 제품군으로 묶는 방식은 제품군 사전 작업에서 확정한다. 제안은 일회용 카메라 1개 + 인스탁스 즉석카메라 2개 상품이며, 상품명에서 읽어낸 것이라 결정된 사항이 아니다. (설계 제안)
- 두 인스탁스 상품은 카메라에 가방·필름·스트랩이 붙은 세트라 리뷰에 카메라 외 요소가 섞여 있을 수 있다. 데이터를 읽어 봐야 알 수 있다. (미확인)

## 4. MVP에서 반드시 되는 핵심 기능

service-definition.md의 "결정 행동" 3개입니다. 서비스 정의에서 후보였던 행동 1, 2, 5는 모두 MVP에서 제외하기로 했습니다(5절).

### 기능 1. 제품군별 결과 확인 (행동 3)

제품군을 골라 설문 집계와 외부 VOC가 결합된 결과를 대시보드에서 본다.
- 가중/비가중을 토글로 전환할 수 있다. 토글은 외부 VOC의 광고성 가중치에만 적용된다.
  - 가중치 = 1 − 광고성 확률(0~1). (결정)
  - 광고성 확률은 외부 VOC에 대해 규칙과 LLM으로 판정하고, 계산은 코드가 한다.
  - 글은 삭제하지 않고 가중만 낮추며, 가중 집계와 비가중 집계를 모두 보여준다.
  - 가중치의 하한(최소값)은 파일럿에서 정한다. (미정)
  - 설문 응답(KOSSDA 구조) 집계는 가중치 변수가 없어 비가중으로 집계한다.
- 회차별 문항 결과를 확인할 수 있다.
- 합성 응답에는 "합성" 라벨이 붙는다.

### 기능 2. 근거 추적 (행동 4)

액션 제안마다 근거 ID로 근거 응답을 근거 뷰어에서 추적한다.

### 기능 3. 회차 리포트 내보내기 (행동 6)

액션플랜과 다음 회차 설문지가 담긴 회차 리포트를 내보낸다.
- 리포트 속 다음 회차 설문지는 초안 상태로 담긴다. 담당자가 문항 초안을 확인·수정해 확정하는 단계(행동 1)를 MVP에 넣지 않기로 했기 때문이다. (결정)
- 시스템은 내보내기까지만 맡는다.

## 5. MVP에서 제외하는 것

service-definition.md의 "범위 밖"에 아래 결정을 더한 것입니다.

- 문항 초안 확인·수정·확정(행동 1): 제외한다. (결정) 다음 회차 설문지는 초안 상태로 리포트에 담긴다.
- 액션 제안 선별·수정(행동 5): 제외한다. (결정) 시스템이 만든 액션 제안이 담당자의 수정 없이 그대로 리포트에 담긴다.
- 담당자 응답 업로드 화면(행동 2): 제외한다. (결정) 응답 데이터는 개발 초기 단계(Phase 0)에서 스크립트로 적재하고, 기능 1~3은 적재된 데이터로 동작한다.
- 설문 발송: 기존 방식을 유지한다.
- 로그인·권한 분리
- 내보낸 리포트를 의사결정자에게 전달하는 일: 시스템 밖의 수작업이다.
- VOC 수집 실행: 정기 자동 실행이 맡으며 담당자 행동이 아니다.

## 6. 성공 기준

성공 기준은 service-definition.md의 확인 기준을 MVP 기능에 맞춰 옮긴 것입니다. 정량 목표는 출처가 없어서 두지 않았습니다.

**기능 1. 제품군별 결과 확인**
- 제품군을 고르면 설문 집계와 VOC가 한 화면에 나온다.
- 외부 VOC의 가중/비가중을 바꾸면 VOC 집계 결과가 바뀐다. 설문 응답 집계는 토글과 무관하게 비가중이다.
- 회차를 고르면 해당 회차의 문항 결과가 나온다.
- 화면에 표시된 수치가 집계 원본과 일치한다.

**기능 2. 근거 추적**
- 액션 제안의 근거 ID를 선택하면 해당 근거 응답이 근거 뷰어에 열린다.
- 모든 제안 문장이 근거 ID를 가진다.

**기능 3. 회차 리포트 내보내기**
- 한 회차의 액션플랜과 다음 회차 설문지가 한 리포트로 내보내진다.

**전체 흐름**
- 문항 → 취합 → 분석 → 액션플랜 → 다음 문항이 한 번 완주하고 회차 리포트가 출력된다. (노션 Phase 6의 확인 기준)
- 시연할 회차 수는 미정이다. 위 기준은 폐루프를 한 번 도는 것까지만 정하고 있다.

**측정 예정 지표 (목표값 없음)**
- 소요 시간 절감: 가설이며, 프로토타입에서 실측 예정이다.
- 골든셋 정밀도·재현율·카파: 측정 예정이다.
- 반복 실행 일치율: 측정 예정이다.
- 이 지표들은 목표값 없이 측정값을 보고한다. 대부분 합성이 아닌 수집 VOC로 잴 수 있다.

**성과 표기 규칙**
- 합성 응답에서 나온 수치는 성과로 쓰지 않는다. 시연에서 합성 수치를 보여줄 때는 "합성" 라벨을 붙인다.
- 정량 목표값은 두지 않는다. 출처가 있는 목표값이 필요해지면 그때 정한다. (미정)
